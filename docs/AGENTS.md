# 文档规范

本文件只规定文档的组织与维护方式。开发流程、代码与插件规范、Git 提交规范统一见 [根目录 AGENTS.md](../AGENTS.md)。

## 目录分工

| 位置 | 保存什么 | 维护方式 |
| --- | --- | --- |
| `design.md` / `design.zh.md` | v1 已发布设计（英文 / 中文）。README 顶层链接指向这两个文件，**保持原位不迁移**。 | 只修订错漏与补充边界说明；设计演进不覆盖原文，新设计文档引用并说明替代范围。 |
| [design/](design/) | 后续新增的设计文档：新能力设计、协议或配置格式演进、跨模块重构方案。 | 只新增文档，保留设计演进过程；命名 `YYYYMMDD-NN-slug.md`（NN 为当日序号）。 |
| [tasks/](tasks/) | 从设计拆分的开发任务与验证文档，以及 bug、重构的方案、进展和结果。 | 一项任务一个文件，命名 `YYYYMMDD-NN-slug.md`，持续更新；多版开发用序号递增并引用前版。 |
| `handoff-dsh-inline-history.md` | DSH 内联侧演进历史与待移植增量的交接材料。 | **仅本地保存，不做 git 追踪**（已在 `.gitignore`）；内容过时后可归档到 `.scratch/`。 |

## 文档维护

- **开发需求建账规则**（与根目录规范对应）：
  - 新增能力、跨模块重构、协议或配置格式变化 → `design/` 新增设计文档 + `tasks/` 新增任务验证文档；
  - 已有设计覆盖的需求 → 不重复建档，在任务文档中引用设计并写清增量；
  - 小 bug 和局部改动 → 可 ad hoc，不强制建文档；是否升级按根目录规范判断。
- 任务文档开头写清**目标、实现路径、验收标准**；实施过程中在同一文件追加进展、调整与验证结果（命令与输出摘要），验收前不删除失败记录。
- `design/` 保留设计演进：已有设计不覆盖、不删除，新设计引用原设计并说明补充或替代范围。
- 任务完成或验证通过后，任务文档保留归档，作为后续改动的依据；不合并、不拆分历史任务文档。
- 文档使用中文（设计文档可中英对照成对维护，如 `design.md` / `design.zh.md`），UTF-8、LF，以换行结束。修改后检查相关路径、链接和示例，保持代码库整洁。
- 临时测试输出、原始日志和试运行材料放仓库根目录 `.scratch/`，不合入代码库；正式文档不链接本地临时材料，必要的长期证据应脱敏后保存。
